Counterexample Generation via Per‑Theorem Symbolic Verifiers

When Imitation Hurts and Reinforcement Repairs

Training a model only on counterexamples makes it treat every theorem as false. Reinforcement learning against a symbolic verifier fixes this, but only when the reward is sparse.

How it works

Take a true theorem, drop one hypothesis, and ask the model for a counterexample. A Python verifier written for that conjecture checks the answer, and the same check is the RL reward.

  1. 1 · True theorem G × H is abelian if and only if G and H are both abelian.
  2. 2 · Drop a hypothesis “If H is abelian, then G × H is abelian.” False.
  3. 3 · Model answers (SymmetricGroup(3), CyclicGroup(2))
    or NONE if it thinks no counterexample exists
  4. 4 · Verifier runs [True, True]
    H is abelian; S3 × C2 is not. Accepted.

One boolean per remaining hypothesis, plus one for the negated conclusion. No language model judges the answer.

The imitation trap

Fine-tuned on counterexamples alone, Qwen3-4B stops recognising true theorems. Two RL rewards then reach the same success rate on false conjectures, but only the sparse one restores calibration.

Qwen3-4B, means over four training seeds. SFT scores 0.00 on true theorems in every seed, and on an explicit true/false question it calls 70% of them false. The collapse also appears on Gemma-3-4B.

Why: what each answer earns

Every training conjecture is false, so answering NONE is never correct during training. The dense reward makes any parsable guess worth more than abstaining. The sparse reward does not, so the model keeps the option of saying NONE, which is what a true theorem needs.
